# RevelAI — website

**Live: [maikotrindade.com/revelAI](https://maikotrindade.com/revelAI/)**

The public face of [RevelAI](../../README.md): what the tool does, what it
refuses to do, and why the honest limitations are on the front page rather than
buried.

> The implementation brief this was built to is [PROMPT.md](PROMPT.md).

## It is a static site, on purpose

RevelAI's promise is that family photographs stay on the owner's machine. A
website that accepted uploads would contradict the thing the product is selling,
so this one builds to static files with `output: "export"` and has **nowhere to
send an image even in principle**. No uploads, no backend, no accounts, no
analytics, no third-party trackers.

## Develop

From the repository root, so pnpm resolves the workspace:

```bash
pnpm install
pnpm --filter @revelai/website dev
```

```bash
pnpm --filter @revelai/website typecheck
pnpm --filter @revelai/website lint
pnpm --filter @revelai/website build     # static export into out/
```

Running `pnpm <script>` from inside `packages/website` makes pnpm treat the
directory as a standalone project and reinstall it. Use `--filter` from the
root.

## Figures

The images are **not committed here**. `scripts/sync-figures.mjs` copies them
from [`packages/engine/docs/img`](../engine/docs/img) into `public/img/` before
every `dev` and `build`, so regenerating them with
`python packages/engine/docs/make_figures.py` updates the engine README and this
site together. A second committed copy would drift the first time somebody
regenerated one and not the other.

Every photograph on the site is synthetic, generated by the engine's own test
fixtures. Nobody's family album is on the internet because of this.

## Theme

Dark follows the operating system **with no JavaScript at all**, and the toggle
overrides it in either direction. The Tailwind `darkMode` variant is:

```
@media (prefers-color-scheme: dark) { &:not(.light *) }
&:is(.dark *)
```

A class-only strategy would leave a visitor with JavaScript disabled
permanently in light mode. A small inline script applies a *stored* choice
before first paint; with no stored choice it writes nothing and the media query
decides.

## Accessibility

Audited with axe-core across four scenarios — OS light, OS dark, and each
overridden by the toggle — on both pages. **Zero violations**, 45 checks
passing on the landing page and 38 on the limitations page.

Two real problems were found and fixed during that audit: muted text inside the
terminal block was dark-on-dark because it used the page's usual muted colour on
a panel that is dark in both themes, and the horizontally scrollable command
blocks were not reachable from the keyboard.

To repeat the audit: build, serve `out/`, then load `axe.min.js` from
`node_modules/axe-core` in the page and call `axe.run`.
