# Contributing to RevelAI

Thanks for helping. RevelAI splits photographs of album pages into individual
photos and, in a separate stage, restores them. The two stages are independent
and must stay that way.

This is a monorepo. Find the package you are working on:

| Package | Language | Guide |
| --- | --- | --- |
| [`packages/engine`](packages/engine) | Python | [engine README](packages/engine/README.md) |
| [`packages/mcp-server`](packages/mcp-server) | Python | [MCP server README](packages/mcp-server/README.md) |
| [`packages/website`](packages/website) | TypeScript | [website README](packages/website/README.md) |

## Monorepo conventions

- **Each package is self-contained.** Its own build config, its own tests, its
  own dependencies. Building or testing one package must never require another
  package's toolchain to be installed.
- **One CI workflow per package**, named `<package>-ci.yml` and path-filtered to
  that package's directory plus its own workflow file. Work on the website must
  not spend twelve runner-minutes re-testing an engine nobody touched.
- **Cross-package dependencies go one way**: the website and the MCP server may
  depend on the engine; the engine depends on neither. If the MCP server needs
  behaviour the engine lacks, add it to the engine, where the tests are.
- **A change touching two packages is still one pull request**, so the two
  halves land together and CI sees them together.

## Development setup: engine

```bash
git clone https://github.com/maikotrindade/revelAI
cd revelAI/packages/engine
python -m venv .venv
source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -e ".[dev]"
```

Run the checks from `packages/engine`:

```bash
pytest -q
ruff check .
ruff format --check .
```

## Development setup: MCP server

```bash
cd packages/mcp-server
pip install -e ../engine -e ".[dev]"
pytest -q
```

## Development setup: website

From the repository root, so pnpm resolves the workspace:

```bash
pnpm install
pnpm --filter @revelai/website dev
pnpm --filter @revelai/website typecheck
pnpm --filter @revelai/website lint
pnpm --filter @revelai/website build
```

Running `pnpm <script>` from inside `packages/website` makes pnpm treat it as a
standalone project and reinstall it. Use `--filter` from the root.

## Ground rules

These are not style preferences; breaking them breaks the product. They apply to
every package, including ones that only call the engine.

1. **`split` never changes pixels beyond one geometric transform.** Exactly one
   resampling per photo — the crop and deskew happen in a single
   `warpPerspective` on the full-resolution original, with `INTER_LANCZOS4`.
   No colour, brightness, contrast, sharpening or noise adjustment lives in
   `split`.
2. **`enhance` never writes into its input folder.** There is a test that the
   input tree is byte-for-byte identical after a run. Keep it passing.
3. **Output folders contain only `photo_XXXXXXXX.png`.** No JSON, no logs, no
   thumbnails, no subfolders. Debug maps, comparisons and index files go to
   separate folders the user asks for by flag.
4. **No crop is ever both wrong and unflagged.** Detection will get things
   wrong; what it must never do is get something wrong quietly. There is a test
   for this across every fixture.
5. **Never commit photographs of real people.** Test fixtures are generated by
   `packages/engine/tests/synth.py`, and the README figures by
   `packages/engine/docs/make_figures.py`. Any real image must be cleared for
   publication by the repository owner.
6. **No test may touch the network or need an API key.** Model and VLM calls
   are mocked.
7. **Classical before model.** In `enhance`, a deterministic offline method is
   tried first; a model is only called for what remains.
8. **Face restoration and colourisation stay off by default**, and anything that
   enables them must surface the warning. They reconstruct and invent; that is
   the whole reason the warnings exist.

## Commits and branches

- [Conventional Commits](https://www.conventionalcommits.org/): `feat:`,
  `fix:`, `test:`, `docs:`, `chore:`.
- **Keep the whole commit message under 20 words** — one subject line. Detail
  belongs in the pull request description, where length costs nothing.
- Prefix the scope when a change is package-specific: `feat(engine):`,
  `fix(website):`.
- Short feature branches, merged by pull request.
- Never force-push `main`.

## Where things live in the engine

| Path | Responsibility |
| --- | --- |
| `src/revelai/split/detect.py` | Page isolation and initial candidates |
| `src/revelai/split/refine.py` | Rotated-rectangle refinement by line integral |
| `src/revelai/split/crop.py` | Inset, sizing, single `warpPerspective` |
| `src/revelai/split/review.py` | Interactive review window |
| `src/revelai/split/inspect.py` | Bridge from split to the VLM |
| `src/revelai/enhance/color.py` | Classical colour correction, no AI |
| `src/revelai/enhance/backends/` | Pluggable restoration backends |
| `src/revelai/vlm/` | Vision-language verification and description |
| `src/revelai/io.py` | Reading, ICC, lossless PNG writing, metadata |
| `src/revelai/naming.py` | Global sequential numbering and ordering |

If you touch `refine.py`, run the geometry tests — they assert IoU ≥ 0.97 and
angle error ≤ 0.3° against synthetic ground truth, which is the whole point of
that module.
